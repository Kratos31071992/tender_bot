# Мониторинг закупок для АСК

Telegram-бот для маленькой фирмы из Нижнего Новгорода. Ищет коммерческие закупки на **Bidzaar**, качает документы, кладёт их в папку и через YandexGPT отвечает: лезть ли в закупку.

Профили фирмы: клининг, металлообработка, монтаж/демонтаж, металлоконструкции, перепродажа металла. Часто работают как перекупы, есть аренда цеха.

Проект учебный (API + SQLite + Telegram), но собран под реальную работу, не «демо на один файл».

---

## Что умеет бот

| Команда / действие | Что происходит |
|---|---|
| `/start` | Проверка, что бот жив, список команд |
| `/fresh слово` | Поиск на Bidzaar, до 5 карточек отдельными сообщениями, кнопки, повтор каждые 15 минут |
| `/stop` | Остановить автообновление |
| `/parse ссылка` | Карточка по ссылке Bidzaar, список файлов, скачивание в `docs/` |
| кнопки «Скачать файлы» / «Анализ» | То же самое с карточки |
| `/analyze` | Читает файлы последней папки и шлёт `analiz.txt` |
| файл в чат | Сохраняет и анализирует |
| `/history` | История твоих `/fresh` и `/parse` |
| `/demo` | Тестовая строка в SQLite |

Источник один: публичное API Bidzaar. ЕИС, Росэлторг и остальные площадки в бота не копируем — нет такой же открытой витрины.

## Как устроен проект

```
tender_bot/
├── bot.py          Telegram: команды, кнопки, папки, запуск анализа
├── parser.py       Поиск, карточка, скачивание с Bidzaar
├── analyze.py      Промпт и вызов YandexGPT
├── database.py     SQLite: закупки, «уже показал этому человеку», логи поиска
├── docs/           Скачанные договоры и ТЗ
├── tenders.db      База (создаётся сама)
├── .env            Секреты, в git не класть
├── requirements.txt
└── README.md
```

Цепочка:

1. `/fresh клининг` → `search_bidzaar` → карточки в чат.
2. Кнопка «Скачать файлы» → `parse_bidzaar` (через `procedureId`) → файлы в `docs/<категория>__<название>__<id>`.
3. Кнопка «Анализ» / `/analyze` → `read_tender_file` (docx, doc, pdf, xlsx, zip) → YandexGPT → `analiz.txt` в ту же папку и в чат.

Анализ смотрит документы, не название. В промпте четыре схемы счёта: себес цеха, работы клининга, монтаж (работа + материал), перепродажа металла (без выдуманных заводских цен).

## База данных

Всё SQL только в `database.py`. Три таблицы:

- `tenders` — найденные закупки (id, название, ссылка, категория).
- `sent_tenders` — кому какую карточку уже показали (`user_id` + `tender_id`). Пользователь Б не теряет выдачу, если пользователь А уже видел ту же закупку.
- `search_logs` — кто, какой командой и что искал. Смотрится командой `/history`.

Категория больше не зашита как «клининг»: её угадывают по названию и слову поиска (`guess_category` в `parser.py`).

## Сеть и файлы

`requests` синхронный. Чтобы бот не замирал на минуту, вызовы парсера, скачивания и Яндекса идут через `asyncio.to_thread`.

Имена файлов с площадки и из чата чистятся (`safe_filename`): нельзя уехать через `../` за пределы папки закупки.

Текст для модели обрезается до 12 000 символов. Ошибка Яндекса не пишется в `analiz.txt` как «успешный анализ» — в чат уходит служебное сообщение.

## Установка и запуск

Нужен Python 3.10+ (у автора стоит 3.14).

```bash
cd ~/Python_BOT/tender_bot
python3 -m pip install -r requirements.txt
```

Файл `.env` рядом с `bot.py` (ключи в чат и в git не класть):

```
BOT_TOKEN=...
YANDEX_API_KEY=...
YANDEX_FOLDER_ID=...
```

```bash
python3 bot.py
```

Проверка: `/start`, потом `/fresh металлопрокат`. На новой карточке — «Скачать файлы», затем «Анализ». `/history` должен показать строку с этим поиском.

Иногда Bidzaar рвёт SSL (чаще с VPN). Поиск и карточка — разные адреса; если кнопки молчат, смотри `procedureId` в `parser.py`.

## Тема для куратора

Telegram-бот мониторинга коммерческих закупок на Bidzaar для малого бизнеса (клининг, металл, монтаж). Есть работа с внешним API, SQLite (закупки + персональная отправка + история запросов), чтение нескольких форматов документов и LLM-разбор «лезть ли новичку» по тексту договора и ТЗ, а не по заголовку.
